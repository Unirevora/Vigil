# 比另一个日记 App 更有用：VIGIL 的产品方向

## 从“记录工具”到“个人线索工作台”

多数日记工具只解决「今天写什么」和「如何保存」。VIGIL 要解决下一个问题：**写过的内容，能否在需要的时候再次帮到我？**

设计原则：本地优先、可迁移、不依赖云端 AI、用户拥有源文件、保留情绪与叙事的原貌，不把私密日记强行变成 KPI 面板。

## 本版已经落地

1. **行动提取与原文回写**：从任意手记的 Markdown `- [ ]` 收集待办、识别 `📅 YYYY-MM-DD` 等日期，按待办与已完成排序。勾选任务会精确写回原始手记行，写入前先做安全快照；如果原文已变化会拒绝盲目覆盖。
2. **双向线索与引用**：解析 `[[手记标题]]`，找出具体引用关系与未解析链接；阅读页呈现有哪些旧手记引用了当前文章。
3. **周期性复盘**：在「线索与行动」聚合近七日记录、连续记录、待办数、双向关联数及高频标签，提供每日轮换的回顾提问，所有计算在本机完成。
4. **可检索的行动历史**：任务既能集中操作，又不会脱离作为上下文的原始文字；按原手记导航即可看到为什么那时做出该决定。
5. **持久化与迁移**：Markdown 原文、五份本地备份、独立加密 JSON 备份，以及已有 GitHub Markdown 仓库编辑，降低平台锁定风险。
6. **场景与知识适配**：日历、节气和往年今日帮助恢复当时场景；支持 LaTeX/KaTeX、任务、表格与内部引用的单窗编辑器适合学习笔记、研究和日志。

## 后续值得做，但本版不能假称已完成

- **语义搜索**：离线嵌入与用户控制的索引，在不上传文字的情况下找回“意思相近”而非只匹配词面的旧记录。
- **自定义回顾计划**：季度/年度线索卡、未完成任务沉淀与归档规则。
- **语音/附件**：离线语音转写、照片与原始资料之间的可回溯引用，不自动上传。
- **多端冲突解决**：GitHub 合并差异、离线编辑队列、版本历史与逐段对比，不静默覆盖远端更新。
- **知识图谱交互**：当链接数大时以可过滤的图形视图浏览引用关系，而非只显示列表。

## 一条完整的用户体验

晚上写下一篇反思，标记了待办 `- [ ] 给导师发邮件 📅 2026-11-20`，并链接 `[[上次的讨论]]`。第二天进入「线索与行动」，就能看到即将到期的事项；点开引用回到原始讨论，完成后勾选，同步反映在手记源码中。下周的回顾提示再帮助用户判断这次行动改变了什么。

这才是“写过的内容还能用起来”的最小闭环，而不只是功能数量更多。
