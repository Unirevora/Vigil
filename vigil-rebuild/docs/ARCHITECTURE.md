# 模块化重构架构说明

## 设计原则

- **先数据，后界面**：所有手记读写统一经 `LocalEntryRepository`。
- **纯业务逻辑**：查询、日期、统计和 Markdown 渲染独立于 DOM，可用 Node 原生测试。
- **视图与事件分离**：`ui/views/*` 只负责生成视图，`main.js` 管理状态、交互和写入。
- **本地优先**：当前不引入账号、网络 API 或云服务。
- **防丢数据**：导入先校验，替换需二次确认；异常数据只读保护，不主动清除旧键。
- **有意识地延后复杂度**：复杂实时预览、自绘组件、节气盘和高级动画均不进入首版。

## 运行流程

```text
浏览器启动
    |
    v
LocalEntryRepository.load()
    |-- 当前新键存在 → 校验并读取
    |-- 新键不存在、上一版原型键存在 → 校验、复制到新键、保留旧键
    |-- 两者都不存在 → 写入四篇可删除的示例手记
    '-- 解析/存储错误 → 只读保护，拒绝覆盖
    |
    v
main.js (状态 + 操作调度)
    |-- core/entries.js      创建、搜索、排序、统计
    |-- core/markdown.js     安全的基础 Markdown
    |-- ui/views/*.js        各个页面模板
    '-- storage/transfer.js  导出与导入
    |
    v
CSS 设计变量 / 响应式页面
```

## 已解决的首版问题

1. 单个 HTML 中样式、业务逻辑、存储逻辑相互耦合的问题。
2. 数据覆盖前缺少数据格式验证的问题。
3. 无法自动复用上一版 **单 HTML 原型** 已有本地手记的问题。
4. 缺乏可独立执行的纯逻辑测试的问题。

## 仍未解决的旧项目集成问题

源材料只有 `CHANGELOG.md`，没有原始源码。以下只能待后续核实：

**禁止在未核对真实数据前，将这些未知格式当作已支持格式导入覆盖。**
