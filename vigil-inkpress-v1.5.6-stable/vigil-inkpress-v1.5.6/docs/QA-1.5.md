- 通过 Chromium 内联打包装载最新多文件项目进行 **21 项浏览器操作检查通过**：高清首页和打字机装饰、玻璃导航、SVG 位移滤镜声明、进入线索页、正式保存/阅读、任务聚合与原文回写、GitHub mock 目录读取/Markdown 预览/PUT 含原 blob SHA、Token 不落盘、外观工坊、320/390/810/1024/1440/1672px 的布局检查及页面异常。

- git-crypt 算法按官方规格重建，通过 Node 的独立 OpenSSL AES-CTR/HMAC-SHA1 实现检查**二进制字节逐一一致**；错误密钥与篡改拒绝解密。

## 仍然需要外部环境/实际数据验收

1. **用户的实际 GitHub 仓库**：尚未提供仓库地址、分支和授权，不能声称已经连接或成功写入用户真实仓库。已核验 GitHub 官方 Contents API 文档并用 mock API 完成读写、SHA 和权限边界测试。界面增加「检查连接」按钮供用户在自己的仓库现场验证。
2. **原生 git-crypt CLI 文件**：此运行环境没有 `git-crypt` 可执行程序，也没有用户的原始加密文件和 export-key。当前按官方源代码格式独立实现，并用独立 OpenSSL 算法比对；还需要一份用户自行提供的真实仓库密文进行最终互操作测试。
3. **复杂 Git 属性规则**：只提供常见通配模式与命名 key 判断，复杂未识别规则拒绝自动提交；需要本地 `git check-attr` 审查。
4. **完整旧版 v2.8.2 迁移**：旧浏览器 LocalStorage、加密备份协议样本未提供，不能宣称无损兼容。
5. **全部 P2**：旧文档中尚有四语言全界面热切换、笔画重组、复杂 3D/自绘日期选择器等；本轮未把这些高成本交互伪装为已经实现。以写作/检索/安全收益优先复原。
6. **字体授权**：代码继续引用用户自带字体路径，但源码 ZIP 不再分发字体二进制；可使用已有的本地恢复脚本。

## 安全复核

- 本地口令加密 JSON 与 git-crypt binary 是不同协议，密钥不会写入 localStorage。
- 受 git-crypt 属性保护的路径无密钥时阻止明文 PUT；未匹配规则时阻止加密 PUT；密钥名不匹配阻止写入；旧 blob SHA 冲突拒绝覆盖。
- AES-CTR 输出使用验证用 HMAC 派生 nonce，解密后先完整验证再返回文本，失败不下载数据。
- 任务勾选前备份旧条目，并检查原文当前行是否仍与页面呈现一致。
- Markdown 原文不用于执行 HTML，渲染仍通过原项目的逃逸策略。
