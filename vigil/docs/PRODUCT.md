# 产品规格与方向 · 不眠手记 VIGIL Inkpress

> 本文合并并取代 `MVP.md`（重构首版规格）与 `PRODUCT-STRATEGY-1.5.md`（产品方向），按**当前代码（1.7.5）**标注实现状态。技术细节见 `ARCHITECTURE.md`，测试见 `QA.md`。
>
> 状态标记：**✅ 已实现** · **🟡 部分实现 / 有边界** · **⬜ 未实现** · **❓ 无法验证**（缺少原项目源码或样本）

## 1. 定位

**轻量、本地优先、以 Markdown 为写作格式的私人手记工作台**，并把已有的 GitHub Markdown 仓库作为与本地并列的第二个文库。

设计原则：

- 本地优先、可迁移、用户拥有 Markdown 源文；不依赖云端服务或云端 AI。
- 数据稳定性优先于任何新功能：损坏数据只读保护，不静默覆盖、不静默迁移。
- 保留情绪与叙事原貌，不把私密日记变成 KPI 面板。
- 不把未实现或未验证的能力写成已完成。

核心闭环：创建 → 编辑 → 保存到本地 → 列表 / 搜索 → 阅读 → 再次编辑；数据可导出、可导入。

进一步的方向（来自 1.5 产品策略）：**从「记录工具」到「个人线索工作台」**——写过的内容能在需要时再次帮到用户：待办可以被找回和完成，引用可以回溯，复盘有提示。

### P0 端到端验收场景（仍作为回归基线）

| 场景 | 步骤要点 | 预期 | 状态 |
| --- | --- | --- | --- |
| 第一次记录 | 新建 → 填标题、日期、Markdown → 保存 → 阅读 → 刷新后重开 | 内容准确、可再次编辑 | ✅ |
| 搜索与维护 | 建 3 篇 → 按标题、正文关键词搜索 → 修改后再搜 → 删除一篇 | 结果及时更新，删除项不再出现 | ✅ |
| 跨环境恢复 | 导出 JSON → 空环境导入 → 逐篇核对 → 导入损坏 JSON | 完整恢复；错误文件不影响现有数据 | ✅ |
| 旧版升级 | 用原项目真实数据运行迁移 → 重启 → 制造不完整数据重试 | 无损、幂等、可恢复 | ❓ 缺样本 |

### 数据模型约定

- `content` 只存 Markdown 源文，不持久化渲染后的 HTML。
- `date` 是手记归属日期，与 `createdAt` / `updatedAt` 分开。
- `legacy` 原样保留暂无法映射的旧字段。
- 本项目的 `schemaVersion: 1` 与原项目提到的「localStorage schema v2」是**两套不同的版本号**，不可混为一谈。
- 业务规则与 DOM 分离，所有持久化经统一 Repository，重要写操作返回成功 / 失败。

## 5. 线索与行动（已落地）

1. **行动提取与原文回写** ✅：从所有手记的 `- [ ]` 收集待办，识别 `📅 YYYY-MM-DD` 等截止日期；勾选时先建快照，并确认原文该行未变，否则拒绝覆盖。
2. **双向线索** ✅：解析 `[[手记标题]]`，列出引用关系与未解析链接；阅读页显示哪些手记引用了当前文章。
3. **周期复盘** ✅：近七日记录、连续记录、待办数、双向关联数、高频标签，以及每日轮换的回顾提问；全部本机计算。
4. **快速组合筛选** ✅：近七天、未完成任务（忽略代码围栏）可与标签、收藏、日期、关键词组合。

完整体验示例：晚上写下 `- [ ] 给导师发邮件 📅 2026-11-20` 并链接 `[[上次的讨论]]`；第二天在「线索与行动」看到即将到期事项，点开引用回到原讨论，完成后勾选，结果写回手记源码；下周回顾提示再帮助判断这次行动改变了什么。

## 6. GitHub 文库（已落地，有边界）

- ✅ 「全部手记」下「本地手记 / GitHub 仓库」两个同级页签；连接成功自动进入 GitHub 页签。
- ✅ 按目录浏览、当前目录文件名检索；远端手记使用与本地相同的阅读稿纸与三态编辑器；新建远端 Markdown。
- ✅ 编辑写入本机草稿（`github:<hash>` 键），只有点击「提交 GitHub」才 PUT；带原 SHA，冲突时保留草稿。
- ✅ git-crypt：导入 export-key 后解密 / 加密提交；`.gitattributes` 规则不明确时拒绝猜测性明文写入；「设置 → 数据」另有本地 git-crypt 文件工坊。
- ✅ 网络诊断：同源中继、HTTP / SOCKS5 本机代理（含 Clash 7897 一键配置）、浏览器链路检查、`npm run diagnose:github`；服务器部署时代理锁定为直连。
- ⬜ OAuth 登录、本地 ↔ GitHub 自动双向同步、远端文件重命名、批量同步、合并差异。
- ❓ 真实私有仓库、组织权限与原生 `git-crypt` CLI 文件的互操作只能在用户自己的环境验证。

## 7. 后续方向（均未实现）

- **语义搜索**：离线嵌入与用户可控索引，不上传文字，找回「意思相近」的旧记录。
- **自定义回顾计划**：季度 / 年度线索卡、未完成任务沉淀与归档规则。
- **语音 / 附件**：离线转写、照片与原始资料的可回溯引用，不自动上传。
- **多端冲突解决**：GitHub 合并差异、离线编辑队列、版本历史与逐段对比，不静默覆盖远端。
- **知识图谱视图**：链接较多时以可过滤图形浏览引用关系。
- **原项目数据迁移**：取得 v2.8.2 真实存储样本与加密协议后，按 MVP 阶段 A「数据审计」重新规划（映射方案、迁移前备份、幂等、失败回滚）。

## 8. 非目标

- 不做跨设备同步服务、账号体系或云端存储。
- 不做完整 Obsidian 插件 / CSS snippets 引擎，不执行任意用户 CSS 或脚本。
- 不声称兼容原项目 v2.8.2 的任何未验证格式。
- 不为视觉效果牺牲数据安全、可访问性或减少动效偏好。
