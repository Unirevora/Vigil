# VIGIL v1.1.0 — 架构与数据保护

## 一、项目分层

```text
index.html ── src/main.js (页面状态与交互)
                 │
                 ├─ src/ui/views/* (纯 HTML 模板)
                 ├─ src/ui/feedback.js (弹窗与提示)
                 ├─ src/core/* (纯功能模块)
                 └─ src/storage/
                    ├─ repository.js (手记正式库)
                    ├─ schema.js (导入校验)
                    ├─ drafts.js (独立草稿暂存)
                    ├─ backups.js (保留最多五份正式库快照)
                    └─ transfer.js (JSON 进出)
```

- 主入口只做状态装配、事件调度和跨模块协调。
- `core` 纯函数不依赖 DOM、网络或 localStorage。
- `views` 单独文件，不直接修改全局状态。
- `storage` 把三份不同用途的数据独立存放，互不覆盖。
- 不引入第三方运行依赖，使用原生 ES Modules。

## 二、三种本地数据

| Key | 用途 | 更新时机 |
| --- | --- | --- |
| `vigil-mvp-data-v1` | 正式手记库 | 点击「正式存档」、导入、删除、恢复历史备份 |
| `vigil-mvp-drafts-v1` | 未正式存档的写作草稿 | 输入防抖约 650ms、离开编辑页、页面隐藏 |
| `vigil-mvp-backups-v1` | 正式手记库历史快照 | 正式存档后、手动备份、删除/导入/恢复之前 |

三个 Key 都有 schema v1。**这与旧项目更新日志提及的旧版 schema v2 不是一回事。**

### 草稿逻辑

1. 用户进入写作页，检查是否有未完成稿。
2. 如果有未完成稿，允许恢复或使用正式版本，绝不无声覆盖。
3. 输入变化后 650ms 通过 `DraftRepository.save()` 同步写入；`visibilitychange`/`pagehide` 再尝试保存。
4. 草稿写入失败时更新状态栏为失败提示；离开编辑前明确警告。
5. 正式存档成功后，只移除该篇对应的草稿，其他草稿不受影响。
6. 新建手记草稿标识为 `__new__`，编辑已有手记草稿标识为条目 ID。
7. 草稿达到 40 份上限时**拒绝自动淘汰旧稿**，防止静默丢失。

### 本地备份逻辑

- 备份内容是完整的正式手记条目数组的快照。
- 每次正式保存产生新快照；最多保留最近 5 份。
- 删除、JSON 替换导入、历史恢复前也创建安全副本，失败则取消破坏性操作。
- 备份恢复会生成恢复前快照，并将选中的条目集合写回正式库。
- 恢复时先复制目标快照，以免创建安全副本导致五份环形队列淘汰该目标。
- 备份损坏时进入该模块保护状态，禁止不安全的覆盖。
- localStorage 空间不足时会明确提示，不能保证自动快照成功。
- 自动快照不包括未发布草稿。外部 JSON 也只导出正式条目。

## 三、关键边界

- 新版 `repository.load()` 优先读取新的正式库 Key。
- 如果新 Key 不存在而旧单 HTML 原型 Key 存在，会先校验再**复制**到新 Key，保留旧数据。
- 任意未知或损坏 JSON 不会被系统自动替换成空数据。
- 原项目 v2.8.2 的 localStorage Key、加密算法、草稿与收藏格式没有源码凭据，未声称兼容。
- Markdown 当前为经过转义的轻量受控渲染器；不支持所有 CommonMark、HTML 扩展或数学公式。
- UI 与本地存储未加密，不能替代隐私保护系统或异地备份机制。

## 四、视觉规范

基调：**近代中式印刷、铅字档案、打字机工作台**。

| Token | 颜色 | 用途 |
| --- | --- | --- |
| `--bg` | `#e9dfcc` | 年代感旧纸背景 |
| `--paper` | `#f7f0df` | 信纸和档案卡片 |
| `--sidebar` | `#34332e` | 深墨棕侧栏 |
| `--ink` | `#292d2b` | 近黑墨印正文 |
| `--accent` | `#a34631` | 朱砂、档案印章 |
| `--jade` | `#354b45` | 机械键盘与主操作按钮 |
| `--brass` | `#ae9770` | 黄铜与微强调 |

项目使用用户提供的 `titlefont.ttf`（标题）和 `textfont.ttf`（正文），可由 `fonts/README.md` 中说明恢复。统一使用窄边线、纸纹、单色压印与少量机械细节，避免玻璃拟态与重粒子动画。

布局宽度回归：320 / 390 / 810 / 1440px。字体未加载时自动降级，不阻塞首屏内容。尊重 `prefers-reduced-motion`。

## 五、测试与发布

```bash
npm test
npm run dev
```

单元测试覆盖手记模型、Markdown 安全、JSON 进出、草稿写入、5 份备份限制、损坏数据及写入异常。浏览器交互测试额外验证新建/编辑/删除、草稿恢复、备份回滚、移动端布局以及无运行时脚本错误。

**发布前必须另做**真实旧版 v2.8.2 数据样本与部署路径的兼容验收，不可仅凭 README 视作生产级无损迁移。
