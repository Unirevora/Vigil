# v1.5.6 GitHub 浏览器仓库链路修复

## 问题与证据

用户的 `npm run diagnose:github` 报告了五项全部 PASS：Node 服务、MANUAL 127.0.0.1:7897 代理、完整 GitHub JSON、公开仓库元数据以及目录。网页“一键连接公开示例（匿名）”仍失败，提示仓库信息阶段请求 `TypeError`。**这证明 Node 外连链路可用，但不能证明当前浏览器可以请求相同的本地 API 路径。** 具体是否因浏览器扩展、安全策略、页面端口不同或其他因素所致，尚无浏览器 Network 证据可确认。

## 本次更改

- 原主路径：`GET /api/github/repos/:owner/:repo`，仍保持。
- 新增备用只读路径：`GET /api/vigil-bridge/repos/:owner/:repo`。两者共享原有的严格 GitHub REST 路由校验和传输代理，不开放通用代理。
- 在公开仓库显式匿名连接模式下，如果浏览器对主路径的 fetch 抛出异常，优先尝试备用同源路径。如果可用，后续目录和 `.gitattributes` 读取也使用备用路径。
- 两个同源路径均不可用时，才尝试浏览器匿名直连官方公共 API。
- 备用路径严格拒绝 Authorization 请求头、PUT 和其他非 GET 请求；包含 PAT 的请求和上传操作不进行不确定的重试，也不会进入备用路径。
- 页面“浏览器链路检查”对四个公开 URL 发出无凭据 GET，请求结果不包括 Token、用户私有仓库地址或正文。
- `npm run diagnose:github` 增加第六项备用路径检查。但它运行在 Node 进程，仍不能替代页面上的浏览器测试。

## 运行与排查

1. 停止旧的 `npm run dev`，解压新包，重新启动，浏览器按 Ctrl+Shift+R 硬刷新。确保网页地址是 `http://127.0.0.1:5173/` 而不是 file:// 或其他旧端口。
2. Clash 保持已经证明可用的 `HTTP / 127.0.0.1:7897`。
3. GitHub → **浏览器链路检查**：四项分别显示 PASS / FAIL。
4. 如果主同源 FAIL、备用同源 PASS，点击 **一键连接公开示例（匿名）**，客户端应自动使用备用路径。
5. 如果两个同源均 FAIL，而 Node CLI 六项 PASS，重点检查浏览器请求拦截与页面实际 origin。可在无扩展的新浏览器配置中对照，但不要关闭 TLS 验证。
6. 如果四项都 PASS，但仍无法连接，请提供页面连接阶段具体错误，定位数据结构和应用状态逻辑。

## 边界

真实用户浏览器、Clash 节点、公开 GitHub 外网连接未在本执行环境直接复现；本文描述的是源码修复、测试环境模拟、以及后续需要采集的实际证据。
