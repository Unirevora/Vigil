# v1.4.1 加密 JSON 备份协议

## 范围声明

这是本次重构**新设计的独立备份文件格式**，并非原项目 v2.8.2 中未验证的加密迁移格式。旧版如何派生密钥、使用何种盐和 IV、文件头如何存储等信息尚未获得源码或样本。**不能用本工具解密旧格式。**

## 导出

进入「门与数据」，点击「加密导出」，输入两次相同的口令（至少 10 字符），随后下载日期标记的 `*.vigil.json` 文件。

- 只包含**正式保存的手记**，不包含未存草稿、浏览器历史快照、GitHub 令牌或 GitHub 仓库文件。
- 明文为当前 `makeDataset(entries)` 对应的 Schema v1 JSON。
- 使用 Web Crypto API；要求 HTTPS 或 localhost 安全上下文。
- AES-256-GCM；PBKDF2-HMAC-SHA256 派生密钥，迭代 600000 次。
- 使用每次随机生成的 16 字节盐与 12 字节 IV，128 位 GCM 认证标签。
- AAD 常量包含格式、版本、算法和迭代信息，以防文件头被静默替换为其他安全参数。
- 口令只保存在本次操作的临时变量和弹窗输入框中，弹窗关闭时清空，不写到 localStorage。
- 如口令忘记，将无法从加密文件恢复数据；应用不提供找回途径。

导出文件示意（下方是结构，不是真实密文）：

```json
{
  "format": "vigil-encrypted-json",
  "version": 1,
  "kdf": "PBKDF2-SHA256",
  "iterations": 600000,
  "cipher": "AES-256-GCM",
  "salt": "<Base64，16 字节>",
  "iv": "<Base64，12 字节>",
  "ciphertext": "<Base64，AES-GCM 密文与认证标签>"
}
```

## 导入

「加密导入」只接受新版格式。「导入手记」也能自动识别此新版加密文件并要求口令。

1. 首先检查整个文件最大 12MB、JSON 格式与加密版本/算法；
2. 要求输入口令，使用 AES-GCM 认证解密；
3. 使用原本的 Schema v1 校验明文数据；如果口令错误、GCM 认证失败、明文 JSON 非法或条目重复，立即报错；
4. 显示覆盖现有手记的确认弹窗；
5. 如果当前手记非空，则先在本地五份快照仓库建立导入前副本；若备份失败，取消覆盖；
6. 只有所有步骤成功后才写入正式手记库。

**不保证本地快照能防止浏览器数据被清除**。加密文件本身在电脑中仍需要安全存放。

## 隐私与威胁模型

- 备份文件静态加密，能降低文件外泄时的直接暴露风险，但强度仍取决于口令质量。
- 这是浏览器端加密导出，不是正在写作或阅读时的端到端加密存储。正式手记和草稿仍存于本地浏览器存储。
- 若网页来源本身被恶意篡改、设备被恶意软件控制、口令过弱、或用户复制明文给第三方，这一功能无法保护数据。
- 请避免在不可信的第三方网页中输入备份口令，不要在公共计算机上导入个人私密手记。
- GitHub 工作区是独立的远端内容，不会进入本地加密备份。

## 自动化测试

`tests/encrypted-transfer.test.js` 检查：中文/emoji 元信息加密往返、随机盐/IV、错误口令、篡改认证、算法/版本不兼容、短口令与错误 Base64。

此功能的浏览器端文件导出应在 HTTPS/localhost 上验收；在不具备安全上下文的 `about:blank` 自动化页面下不可使用 SubtleCrypto。
