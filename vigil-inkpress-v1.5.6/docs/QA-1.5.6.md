## 已验证

- Node 单元测试：`npm test`，所有测试通过（见最终测试日志）。
- 本地服务：通过 `npm run dev` 启动，HTTP 请求验证 `/`、`/assets/vigil.css`、`/src/main.js`、壁纸及 `/api/github/health` 都返回 200。
- 浏览器：由于当前运行环境的 Chromium 策略阻断 localhost 和外部 URL，使用基于**实际项目代码及静态资源**的离线夹具；检查 320、390、810、1440px 的日间与夜间页面：首页、列表、日历风物、线索、GitHub、设置以及新建编辑器，共 56 个视图/尺寸/主题组合，均无横向溢出或 JS 异常。
- 夜间实测 `topbar` 背景为透明，统计数字和辅助标签采用亮色，并与深色卡片成对设置。
- GitHub 单元：固定目标 URL、同源来源限制、模拟仓库读取与 SHA 提交、DNS 失败结构化响应、NO_PROXY 和 HTTPS_PROXY CONNECT 状态。
- CSS 结构：24 个源码文件 → 1 条浏览器运行时请求，层叠次序仍严格由 manifest 定义。

## 尚未验证 / 外部环境依赖

- 本运行环境限制 Chromium 直接访问 localhost，同时 GitHub 公网访问可能受 DNS 策略约束。因此**不能声称已连接真实私人仓库**，也不能保证用户网络的 DNS、代理出口和账号权限已经恢复。
- 用户需要在自己的设备运行 `npm run dev`，于 GitHub 页面点击「测试 GitHub 网络」。若失败，请检查应用显示的 `EAI_AGAIN` / `PROXY_CONNECT_*` / `TIMEOUT` 等诊断，并提供受限的 `HTTPS_PROXY`。
- git-crypt 的真实私有文件交互需要用户自己的有效密钥和仓库，当前保留已有安全边界，未进行真实写操作。
- 用户所持有的标题和正文字体并未直接包含在项目 ZIP 中，仍可用本地脚本恢复；这不会影响项目使用系统字体回退。
